# 0.3.0 design brief: inflate

**Status: design brief. Not implemented.** Sections 0-11 are the problem
statement, the constraints, the proposed surface and the test plan. Section 12
is where the deviations get recorded once this is built, as it was for
[0.2.0](0.2.0.md).

Read [../internals.md](../internals.md) first: the memory model, the pinned
layouts, the FFI review gates and the streaming-value conventions all apply
unchanged.

## 0. What changed after review

The first draft was reviewed by a third party who does not write Goose. Four
blocking items were raised, plus seven edge cases. Four of the blockers were
real; one rested on a wrong reading of ISA-L; one pair was half right in each
direction. Each verdict below is backed by the compiler, the vendored source, or
a measurement against the 2.32.1 pin — none of it is preference.

| Claim | Verdict | Evidence | Change |
|---|---|---|---|
| `inflate` cannot take `out: u8[>..]&`: a builder has no `.cap`, so there is no honest `avail_out` for an unbounded decode | **right, blocking** | `references/language.md`: `.cap` "exists only on `T[..k]` and `T[..]`", and a builder's elements are the caller's data stack. `igzip_gs_compress` writes at `b.stk->top` only because `igzip_gs_bound` computes the worst case first; there is no inflate bound | `inflate` takes `dst: u8[:]`, the shape `igzip_gs_writer_step` and `igzip_gs_writer_gzip_header` already use |
| `read` must keep draining after `block_state == ISAL_BLOCK_FINISH` or up to 64 KiB of tail is lost | **wrong premise, right worry** | 200,000 one-byte-output calls over a 200 KB body: `FINISH` is set only when `tmp_out_valid == tmp_out_processed` (`igzip_inflate.c` ~2433), i.e. the staging buffer is *provably* empty at `FINISH`. Nothing can be staged there | no post-`FINISH` drain exists to write. But `finish` loses its `out` parameter, and the case that *does* leave output staged — a destination smaller than the chunk, i.e. a step-level caller — drains with the documented `read(r, "", out)`, which `read` itself never needs |
| The phase rules around a member boundary contradict `finish` | **right** | §6 said the one-shot verbs leave the reader `Finished`, while `finish` was "the mirror of `Writer.finish`" and nothing said what `read` does to the phase | §5 Q11, a transition matrix with one row per verb |
| `total_in`/`total_out` cannot be both fields and functions | **right, and it does not compile** | `goose check`: `error: field total_in is not callable` | fields only, as on `Writer`; the raw mirror is renamed `istate` to match `Writer.stream` |
| `isal_inflate_stateless` may overrun a short destination the way `isal_deflate_stateless` does | **measured: it does not** | an exact 200,000-byte destination decoded clean; one byte short returned `ISAL_OUT_OVERFLOW` having written exactly 199,999 bytes, with no fault across a `PROT_NONE` guard page flush against the end of the destination | §9 risk 1 retired; `TooSmall` is implementable and safe |

Accepted from the review without argument (each is now in the section it
belongs to): `inflated` must call `finish` (an empty `src` otherwise reports
success on truncated input); `read(r, "", out)` must not trip the zero-progress
guard; the stateless verb must refuse a reader that has a dictionary; `set_dict`
rejects `Wrapper.Gzip` and caps `dict.len`, and an empty dictionary cannot
satisfy FDICT; every shared field gets an `offsetof` assert and the forged-copy
check; a worker holding both values must stay off macOS's 512 KB pthread stack;
`test/large_stream.goose` must pipe compressed chunks into the reader instead of
buffering them; and `NeedDict` needs its own row in the transition matrix.

One correction to the review's reasoning, recorded so it is not re-derived: it
said `isal_inflate_stateless` "calls `isal_inflate_reset` internally, which
silently wipes any dictionary". It does not call reset; it clears a subset of
fields inline and leaves `tmp_out_processed`/`tmp_out_valid` — the only place a
dictionary actually lives — untouched. The guard is still right, for the
documented reason: ISA-L documents the stateless path as dictionary-free, and
0.3.0 should not lean on an undocumented side effect.

## 1. What the library is, and where it stands

`goose-igzip` binds **igzip** — ISA-L's gzip implementation — to Goose. It is a
Goose package: `igzip.goose` is the entry, `igzip.build` names the CMake target
`igzip_goose`, and `src/igzip_shim.c` is the C adapter. ISA-L 2.32.1 is a pinned
submodule built from source; nothing is installed system-wide.

```bash
make check        # typecheck the package
make test         # Goose tests, then inflate every stream they wrote
make verify       # check + tests + thread test + large test + examples
make stress       # AddressSanitizer check of the output bound
make fmt          # layout is goose format's decision
```

Both halves of *compression* ship today:

| | |
|---|---|
| `Compressor` | 299,472 B — stateless deflate, levels 0-3, raw/gzip/zlib |
| `Writer` | 367,280 B — streaming deflate, custom headers, flush points, dictionary |
| `Trainer`, `Histogram`, `HuffTables` | 18,912 / 2,528 / 2,232 B; trained tables for level 0 |
| `Status` + `ok` / `status_name` | the only failure channel; nothing aborts on bad input |

There is no decompressor. Every test that proves a stream is valid leaves Goose
and runs CPython's `zlib`/`gzip` through `scripts/check_gzip.py`; `make test`
fails if `python3` is missing.

## 2. The problem: this is the version that makes the package a codec

Four things change at once, and they are one design problem because they share
the same state object and the same failure surface.

1. **The package cannot test itself.** A compressor returning `Ok` with a
   plausible size can still emit a broken stream — AGENTS.md says so, and that
   is why the Python checker exists. A decompressor turns every existing test
   into a self-checking one, and is the only way `make verify` can ever run on a
   machine without Python.
2. **`isal_inflate` is stateful and has a different contract from
   `isal_deflate`.** It resumes through `avail_out` reaching zero, sends the
   LZ77 history through its own `tmp_out_buffer`, and signals "member ended"
   with a block state that is *not* an error code. The verb shape has to be
   chosen against that, not copied from `write`.
3. **Input consumption is not total.** Compression consumes every byte handed
   to it. Decompression stops at the end of a member and leaves the rest of the
   slice untouched, which is what makes concatenated members and trailing bytes
   expressible. A `write`-shaped `read(...) -> Status` would silently discard
   that information.
4. **This is the package's first untrusted-input path.** Until now the caller
   fed igzip bytes the caller produced. A decompressor is fed whatever arrived
   on the wire: truncation, bit flips, a fabricated header, a wrapper that
   claims a different method, and the expansion bomb.

The natural consumer is a server that already holds a per-thread `Writer` and
now needs the reverse direction — request bodies, cached entries, proxied
upstreams. Budget accordingly: a `Reader` sits next to a `Writer` for
~152,936 B (below), not another 367 KB.

## 3. Hard constraints

- **C owns no memory.** No `malloc`, no handle to close. State lives in the
  Goose value and the owning scope is the free.
- **No API break.** Every 0.1.0 and 0.2.0 signature keeps working and producing
  the same bytes.
- **Layouts pinned.** Every new mirrored C struct gets `_Static_assert`s for
  size, alignment, and each offset the shim reads.
- **Build shape unchanged.** Native code is the CMake target `igzip_goose`; no
  `c_libs`, no `extern "isal"` block, no system install.
- **Goose has no named arguments, no tuples, no `?`, and no truthiness.** A call
  site reads positionally; a `Status` needs `.ok()`; a group of results is a
  multiple return (`-> i64, Status`), not a struct.
- **No progress is never a hang.** Every drain loop gets the `write_window`
  guard: `used == 0 && written == 0` is a `Status`, never an infinite loop.

## 4. ISA-L facts you can rely on

Measured against the vendored 2.32.1 pin unless marked otherwise.

### The state value

| Item | Value | Consequence |
|---|---|---|
| `sizeof(struct inflate_state)` | **87,368 B**, align 8 | the reader's whole state; no level buffer, no hufftables pointer |
| `lit_huff_code` / `dist_huff_code` | 18,912 / 2,208 B | most of the 87 KB: decode lookup tables, rebuilt per block |
| `tmp_out_buffer` | 65,824 B (`2*32768 + 288`), offset 21,544 | igzip's own 64 KiB history; a drain through a 64 KiB chunk cannot lose it |
| `tmp_in_buffer` | 328 B | header bytes held across a chunk boundary |
| `total_out` | `uint32_t`, offset 12 | wraps exactly like gzip's ISIZE, which is why `check_gzip_checksum` compares a wrapped value. Do **not** accumulate it by delta: `isal_inflate` subtracts its still-staged bytes at the end of every call, so a delta can be negative. The reader counts the bytes it delivered instead (§6) |
| `block_state`, `crc_flag`, `wrapper_flag` | offsets 21,160 / 21,172 / 21,204 | completion, wrapper, and "header already parsed" |

### The functions

| Fact | Consequence for the design |
|---|---|
| `void isal_inflate_init(struct inflate_state *)` / `isal_inflate_reset` | reset clears `wrapper_flag`, `dict_length`, `tmp_in_*`, `tmp_out_*` and the overflow cursors, but **not** `crc_flag` or `hist_bits` — exactly right for the next concatenated member |
| `int isal_inflate(struct inflate_state *)` returns `ISAL_DECOMP_OK` (0) or a negative error | the tail is `return (ret > 0) ? ISAL_DECOMP_OK : ret`, and the only positive code that escapes is `ISAL_NEED_DICT`. **"Done" is `block_state == ISAL_BLOCK_FINISH`, not a return code** |
| `isal_inflate` resumes after `avail_out == 0` via `copy_overflow_length` / `write_overflow_*` into `tmp_out_buffer` | an honest `avail_out` every call is the whole contract; a chunked drain is safe and byte-identical to a one-shot (asserted in the tests, not assumed) |
| with input exhausted mid-block and `avail_out > 0`, `isal_inflate` returns 0 and consumes everything | truncation is *observable only* as `block_state != FINISH`; `read` must not bend this into `Corrupt` |
| `isal_inflate_stateless` resets its own decode fields on entry and decodes exactly one member | a retry with a bigger destination is well-defined; trailing bytes are left in `avail_in` |
| `isal_inflate_stateless` returns `ISAL_END_INPUT` (1) when the final block was never reached | the roadmap's "truncated input is its own `Status`", for free |
| `isal_inflate_stateless` (**documented**) does not support dictionaries | `NeedDict` is the answer there; dictionary streams work through the streaming path |
| `isal_inflate_set_dict` memcpy's at most `IGZIP_HIST_SIZE` (32 KiB) of the tail into `tmp_out_buffer` and requires `block_state == NEW_HDR && tmp_out_processed == tmp_out_valid` (it does not look at `total_out`) | the slice does not outlive the call, and the legal moment is "before any output", which includes *just after* `ISAL_NEED_DICT` |
| `dict_length` is written by `isal_inflate_set_dict` and by both resets and is **read by nothing** | the dictionary works purely through the `tmp_out_buffer` history, so `set_dict` cannot validate one — which is the mechanism behind the `dict_id` row below |
| measured: `block_state` only reaches `ISAL_BLOCK_FINISH` with `tmp_out_valid == tmp_out_processed` (200,000 one-byte-output calls over a 200 KB body) | `finished(r)` means every decoded byte has already been handed to the caller; `finish` needs no output buffer |
| measured: `isal_inflate` with `avail_in == 0` and room copies staged bytes out (4,053 delivered in one call after the caller's 1-byte buffer filled) | an empty-source call is the drain step. `read` loops internally so it never needs one; a caller driving `igzip_gs_reader_step` with a small destination does, which is why `read(r, "", out)` stays legal |
| measured: `isal_inflate_stateless` into a destination one byte short writes exactly `dst.len` bytes and returns `ISAL_OUT_OVERFLOW`; into an exact-size destination it returns `ISAL_DECOMP_OK` | unlike `isal_deflate_stateless`, stateless inflate is honest about `avail_out`; `TooSmall` is a real, safe answer |
| measured: none of the sampled truncations of a valid member (every offset below 64, then every 97th) left `block_state == FINISH` | truncation is exactly `!finished(r)`, with no false completions to special-case |
| a zlib stream with FDICT makes `isal_inflate` parse the header, store `dict_id`, and return `ISAL_NEED_DICT` (6) | `read` must report it *with the header bytes consumed* so the caller can supply the dictionary and continue from the same offset |
| **`dict_id` is stored and never compared** (`igzip_inflate.c` 2114 / 2257; no comparison anywhere) | a wrong dictionary is not caught at `set_dict`. With a wrapper, the trailer catches it (`INCORRECT_CHECKSUM`); on `Wrapper.Raw` there is no trailer and nothing catches it at all — the caller gets plausible wrong bytes and `Status.Ok`. Say so, and pin it with a test |
| return codes: `ISAL_DECOMP_OK 0`, `END_INPUT 1`, `OUT_OVERFLOW 2`, `NEED_DICT 6`; `INVALID_BLOCK -1`, `INVALID_SYMBOL -2`, `INVALID_LOOKBACK -3`, `INVALID_WRAPPER -4`, `UNSUPPORTED_METHOD -5`, `INCORRECT_CHECKSUM -6` | **-1 and -3 collide with the deflate family's `STATELESS_OVERFLOW` and `ISAL_INVALID_STATE`**, so one shared `status_of` cannot serve both. The shim must translate (Q8) |
| `ISAL_DEFLATE 0`, `ISAL_GZIP 1`, `ISAL_ZLIB 3` are the `crc_flag` values | `wrapper_code()` already returns 0/1/3, so the same Goose `Wrapper` maps directly |
| no globals in `igzip_inflate.c`; every byte is in the caller's struct or lent for one call | a `Reader` per `thread_fn` works exactly like a `Writer`, with no `main_thread_only` |

## 5. Design questions

### Q1 — One `Reader`, or a streaming type plus a one-shot type?

`isal_inflate_stateless` needs the same 87,368-byte `inflate_state` as
`isal_inflate`, so a separate `Inflate` type would duplicate the largest part of
the value for anyone who wants both paths.

**Recommend: one value, two modes.** `Reader` carries the state, a 64 KiB chunk,
a wrapper, a phase and a copy guard; `read`/`finish` drive `isal_inflate`, and
`inflate` is the direct `isal_inflate_stateless` exposure, with `inflated` as the
fresh-builder convenience on top of the streaming loop. The phase enum already
distinguishes the legal moments (Q11), so there is no extra mode flag.

### Q2 — Naming

The roadmap says `Inflater` "matching `Deflater`", but the type that shipped is
`Writer`. gslib's prior art is `GzipReader` / `gzip_reader` / `gzip_read`.

**Recommend `Reader`**, with `reader(wrap)`, `gzip_reader()`, `zlib_reader()`,
`raw_reader()`, and the streaming verb `read` so the two shapes line up:

```goose
w.write(plain, out);        r.read(gz, out);        // streaming, append to a builder
c.compress(plain, out);     r.inflate(gz, dst);     // one-shot, caller's room (a slice)
c.compressed(plain);        r.inflated(gz);         // one-shot, fresh buffer
```

`inflate`/`inflated` keep ISA-L's own word for decompression, which is also what
a caller searching for "inflate" will type.

### Q3 — Where does output go?

Same two shapes as 0.2.0, plus one that only exists for inflate.

(a) **owned 64 KiB chunk, appended per call** — proven by `Writer`, works with a
destination builder that has zero free space.
(b) **decode straight into the builder's free space** and claim what igzip
wrote. No copy, but Goose offers no `reserve` on a builder, so a builder with no
slack leaves `avail_out == 0`; the loop would have to `resize` up and down, and
growing an array while an outstanding `const u8[:]` views it is not legal Goose.
(c) **caller-sized destination, no staging** — this is what the *stateless* verb
needs anyway, because igzip cannot say how much output a member will produce.
It has to be a writable slice, **`dst: u8[:]`**, and cannot be a builder. A
builder has no `.cap` and its elements are the caller's data stack, so `avail_out`
would have to be invented: the remaining stack (`TooSmall` could never fire and
an overrun would be silent) or a guess (an overrun outright). `igzip_gs_compress`
can write at `b.stk->top` only because it computes `igzip_gs_bound` first, and
no inflate bound exists. `igzip_gs_writer_step` and
`igzip_gs_writer_gzip_header` already take `dst: u8[:]` and set
`avail_out = (uint32_t)dst.len`, so this is the package's established shape.

**Recommend (a) for `read` and (c) for `inflate`.** `finish` produces no output
at all (Q11). The chunk is 64 KiB on top of 87 KB; that is the whole budget:
**`Reader` = 152,936 B** (87,368 state + 65,536 chunk + 3 u64 counters + 3 bytes
of flags).

### Q4 — What does `read` return?

Compression consumes everything, so `write(...) -> Status` is complete.
Decompression stops at a member boundary with bytes left over, and a caller that
cannot see where needs to re-scan the buffer or re-feed it — a correctness
error waiting to happen for concatenated members and trailing bytes.

**Recommend `fn read(r: Reader&, src: const u8[:], out: u8[>..]&) -> i64, Status`**
returning the number of *compressed* bytes consumed. The loop stops when `src` is
exhausted **or** the member ends. `consumed == src.len && r.finished()` is the
common one-member case, and it reads as one condition.

```goose
var r = igzip::gzip_reader();
var body: u8[>..] = [];
let used, err = r.read(gz, body);
guard err.ok() else { abort(igzip::status_name(err)); };
guard r.finished() else { /* need more input */ };
// gz[used..] is not this member's: trailing bytes or the next member.
```

`read` windows its input at `MAX_INPUT` like `write`, and exposes the same
`read_windowed(r, src, out, step)` test seam so the 32-bit path is reachable
without a 2 GiB slice. A `src` past `MAX_INPUT` is windowed, never rejected.

### Q5 — Concatenated members: automatic or explicit?

`gzip.decompress` concatenates; Go defaults `Multistream` to on; gslib carries a
`multistream` flag to turn that off. A streaming consumer that must know where a
member ends cannot use a silent auto-reset, and a whole-buffer consumer does not
want to write the loop.

**Recommend: explicit in the streaming path, automatic in the whole-buffer
verb.** `read` stops at a boundary and the caller calls `reset(r)` to start the
next member; `inflated(r, src)` loops members itself. No mode flag: `consumed`
plus `finished(r)` already expresses both policies, and a flag would make the
two features disagree.

```goose
// whole buffer: every member, none left behind
let plain, err = r.inflated(two_members);

// streaming: know exactly where member N ends
var pos: i64 = 0;
loop {
    let used, err = r.read(buf[pos..], out);
    if err != igzip::Status.Ok { break; }
    pos += used;
    if !r.finished() { break; }        // the caller stopped feeding, may resume
    if pos == buf.len { break; }       // the last member ended
    r.reset();
}
// At a member boundary `read` has already delivered every decoded byte: there
// is no tail held back (measured, §4). What is left to ask is whether a member
// ever ended.
let err = r.finish();
```

### Q6 — Truncation

Three distinguishable situations, three answers:

| Situation | Reported |
|---|---|
| input ends mid-block, streaming, caller says there is no more | `finish(r)` → `Status.Truncated` |
| input ends mid-block, whole buffer | `inflate`/`inflated` → `Status.Truncated` (ISA-L's `ISAL_END_INPUT`, mapped) |
| input ends mid-block, but the caller has more coming | nothing: `read` returns `Ok`, `finished(r)` is false |

`Truncated` is a distinct variant, never `Corrupt`: truncated data is the normal
case for a cut-off transfer and the remedy (feed more, or re-fetch) is different
from the remedy for damaged bytes (drop it).

### Q7 — Dictionaries

`set_dict` is legal where igzip says it is, which for a *reader* means two
moments, not one:

- **`Fresh`**, before any input: the raw-stream route, and the zlib route where
  the caller knows the stream needs it.
- **`Open`, immediately after `Status.NeedDict`**: the zlib FDICT route. The
  header has been parsed, `block_state` is `NEW_HDR`, no output has been
  produced, and igzip's own guard accepts it. This is the common case for a
  reader and must not be refused.

Three facts the API must state rather than hide: igzip copies the last 32 KiB, so
the slice need not outlive the call; igzip **never compares the supplied
dictionary to the stream's DICTID**, so on a wrapped stream a wrong dictionary is
reported as `BadChecksum` at the trailer, not at `set_dict`; and on
`Wrapper.Raw` there is no trailer, so a wrong dictionary is **undetectable** —
the caller gets plausible wrong bytes and `Status.Ok`. The doc comment says so,
because a caller who expects a status for that will otherwise ship it.

An empty dictionary is `Status.Ok` and a no-op, exactly as on `Writer`: it
cannot satisfy FDICT, and the decode fails later as `Corrupt` or `BadChecksum`.
`set_dict` refuses `Wrapper.Gzip` (`BadState`, matching `Writer.set_dict`) and
`dict.len > MAX_INPUT` (`Overflow`). The stateless verb refuses a reader with
`has_dict` set (`BadState`): ISA-L documents `isal_inflate_stateless` as
dictionary-free, and the supported route is the streaming one.

`reset(r)` drops the dictionary (`isal_inflate_reset` clears `dict_length`), so
a caller reusing a reader for another dictionary stream re-sets it. `reset`
keeps the wrapper, and it must: `crc_flag` survives igzip's reset by design,
which is why the next member's trailer is still verified.

### Q8 — `Status` additions, and the return-code collision

The deflate family maps `-1` to `Overflow` and `-3` to `BadState`; the inflate
family uses `-1` for `ISAL_INVALID_BLOCK` and `-3` for `ISAL_INVALID_LOOKBACK`.
One shared `status_of` table cannot be right for both, and a "look at the call
site" rule is the kind of thing that survives right up until a helper forwards
an `rc`.

**Recommend: the shim translates.** `igzip_gs_reader_*` returns package codes in
a range disjoint from ISA-L's, so `status_of` stays one table and every call site
keeps working:

```c
#define IGZIP_GS_TRUNCATED  (-11)
#define IGZIP_GS_NEED_DICT  (-12)
#define IGZIP_GS_TOO_SMALL  (-13)
#define IGZIP_GS_CORRUPT    (-14)
#define IGZIP_GS_BAD_SUM    (-15)
```

and five new variants, each with an accurate `status_name`:

| Variant | Meaning | From |
|---|---|---|
| `Truncated` | input ended before the member's final block | `ISAL_END_INPUT`, or `!finished` at `finish` |
| `TooSmall` | the caller's destination had no room for the decoded bytes | `ISAL_OUT_OVERFLOW` |
| `NeedDict` | a zlib stream requires a preset dictionary | `ISAL_NEED_DICT` |
| `Corrupt` | the bytes are not a valid deflate stream | `INVALID_BLOCK`, `INVALID_SYMBOL`, `INVALID_LOOKBACK` |
| `BadChecksum` | the trailer does not match the decoded bytes | `INCORRECT_CHECKSUM` |

Reused: `BadWrapper` for `INVALID_WRAPPER` and `UNSUPPORTED_METHOD` (a file
that is not gzip, or gzip with `CM != 8`), `BadState` for `ISAL_INVALID_STATE`,
and `Overflow` keeps its compression-only meaning ("input too large for igzip's
32-bit lengths") so no caller can misread it. `Corrupt` collapses three ISA-L
codes because the caller's remedy is identical for all three; a caller that
wants the exact symbol asks ISA-L, not this package.

`ISAL_INVALID_STATE` (-3) needs no translation and is passed through as it is:
`isal_inflate` never returns it, so the only reader call that can produce a -3
is `isal_inflate_set_dict`, where `BadState` is already the right answer. That
is one fewer place for the table to disagree with itself.

### Q9 — Expansion limits

There is no `bound` for decompression: a 300-byte input may legitimately expand
to gigabytes. That is a hazard for any server that decompresses a request body.

**Recommend: no limit parameter in the 0.3.0 surface.** `read` plus
`r.total_out` is already a limit — a caller stops feeding input when the output
passes its cap, which is strictly better than aborting mid-member.
`inflated`/`inflate` are for buffers whose size the caller already trusts, and
their doc comment says so. Revisit (`inflated(r, src, limit)` as an additive
overload) if a real caller asks.

### Q10 — Copy semantics

Goose copies fixed-size values by assignment. A copied `Reader` is *memory-safe*
— unlike a copied `Writer`, no internal pointer is left dangling, because
`inflate_state` holds no pointer into Goose memory between calls — but both
copies decode from the same position and emit the same bytes twice. Silent
duplication is a bug worth a `Status`.

**Recommend: keep the guard.** Reuse the `Writer`'s `pinned_self` pattern
(lazy init records the value's address; any later call from another address is
`BadState`; `reset` recovers), so the package has one rule for stateful values
rather than a per-type footnote. The shim also clears `next_in`/`next_out` after
every call, the same way `igzip_gs_writer_step` does.

### Q11 — The transition matrix

The first draft named three phases and never said which verb moves between them.
That is the one place a caller loop can be silently wrong — the concatenation
loop and the streaming loop differ exactly here — so the rule is written down.

| verb | `Fresh` | `Open` | `Finished` |
|---|---|---|---|
| `read` | `Ok`, → `Open` | `Ok`; **stays `Open` even when `finished(r)` becomes true** | `BadState` |
| `finish` | `Truncated`, → `Finished` | `finished(r)` ? `Ok` : `Truncated`, → `Finished` | `BadState` |
| `reset` | `Ok`, stays `Fresh` | `Ok`, → `Fresh` | `Ok`, → `Fresh` |
| `set_dict` | `Ok` if raw/zlib, sets `has_dict` | `Ok` only in the moment igzip allows (`block_state == NEW_HDR`, i.e. immediately after `NeedDict`); `BadState` otherwise, from igzip's own guard | `BadState` |
| `inflate` | `Ok` → `Finished`; `TooSmall` → stays `Fresh`; any other status → `Finished` | `BadState` | `BadState` |
| `inflated` | → `Finished` | `BadState` | `BadState` |
| `finished`, `total_in`, `total_out`, `reader_size` | any | any | any |

Two rules make that table hold together:

- **`read` never ends a body.** A member boundary is a fact, not a state
  change: it is `finished(r)`. A caller that stops feeding input may still
  resume, and only `finish` (or `reset`) closes the body. This is what keeps the
  two caller loops in Q5 both correct, and it is why a second `read` after a
  member ended is not an error — `read` of a finished member returns `Ok`,
  `0` consumed, and no output until the caller resets.
- **A terminal error latches.** Once `read` returns `Corrupt`, `BadChecksum` or
  `BadWrapper`, the reader is `Finished`, so a caller that ignores the status
  and loops cannot get a stream of `Ok`s out of a dead state — which is exactly
  what `isal_inflate` would give it, because a `FINISH` block state makes every
  later call return `ISAL_DECOMP_OK` without touching the bytes. `NeedDict` is
  the one status that does not latch: it is a request, and the next call is
  `set_dict` then `read`, both still `Open`.

## 6. The proposed surface

```goose
enum ReaderState { Fresh, Open, Finished }

struct Reader {
    istate:      u64[10921]      = [0; 10921]   // sizeof(inflate_state) = 87,368
    chunk:       u8[CHUNK_SIZE]  = [0; CHUNK_SIZE]
    pinned_self: u64             = 0
    total_in:    u64             = 0
    total_out:   u64             = 0
    wrap:        Wrapper         = Wrapper.Gzip
    state:       ReaderState     = ReaderState.Fresh
    has_dict:    bool            = false
}

fn reader(wrap: Wrapper) -> Reader
fn gzip_reader() -> Reader
fn zlib_reader() -> Reader
fn raw_reader() -> Reader

fn read(r: Reader&, src: const u8[:], out: u8[>..]&) -> i64, Status
fn read_windowed(r: Reader&, src: const u8[:], out: u8[>..]&, step: i64) -> i64, Status
fn finish(r: Reader&) -> Status
fn reset(r: Reader&) -> Status
fn finished(r: Reader&) -> bool

fn set_dict(r: Reader&, dict: const u8[:]) -> Status

fn inflate(r: Reader&, src: const u8[:], dst: u8[:]) -> i64, i64, Status
fn inflated(r: Reader&, src: const u8[:]) -> u8[>..], Status

fn reader_size() -> i64
```

`total_in` and `total_out` are fields, `u64`, updated by the shim — not
getters. A Goose field and a UFCS function cannot share a name (`error: field
total_in is not callable`), and `Writer` already exposes both as fields, so a
getter pair would have been a per-type exception to a rule the package has. The
shim adds the bytes it actually delivered to each caller call; it never adds
deltas of igzip's `total_out`, which is 32-bit *and* can go backwards, because
`isal_inflate` subtracts its still-staged bytes at the end of every call.

Notes on the verbs:

- `read`/`finish` operate on `isal_inflate`; `inflate` on
  `isal_inflate_stateless`. The one-shot verbs are legal only in `Fresh`;
  `reset` is how either mode starts the next body, and the transition matrix is
  Q11. Mixing them inside one body is `BadState`, not undefined.
- `inflate` is the direct stateless exposure and needs the destination to fit:
  that is the roadmap's "whole-buffer read", and the only verb that can answer
  `TooSmall`. It returns `consumed, written, Status`: the destination is the
  caller's slice, so the byte count cannot be inferred from `out.len`. `TooSmall`
  leaves the reader `Fresh` with exactly `dst.len` bytes written, so the caller
  can retry with a bigger slice and no `reset`.
- `inflated` does **not** call the stateless function. It drives the streaming
  loop: a fresh builder cannot be sized ahead of time, the streaming path needs
  no guess, and it is what lets a dictionary work through `inflated`. It ends
  with `finish(r)` — a loop that stops because `src` ran out returns `Ok` from
  `read` and must still be told the body is incomplete, so `""` is `Truncated`
  and not a silent empty success. On any non-`Ok` status the partial output is
  returned beside the status, as `compressed` does; the doc comment says to
  discard it, because it is not authenticated plaintext.
- `finish` takes no output, because it has none to give: `read` cannot return
  with a member ended and bytes still staged (measured, §4). It reports
  `Truncated` if `finished(r)` is false, and otherwise `Ok`. Same shape as
  `Writer.finish`, minus the buffer.
- `finished` is the completion predicate for both modes: `block_state ==
  ISAL_BLOCK_FINISH`. It is the one thing `isal_inflate` cannot tell you through
  its return value.
- `read` accepts an empty `src`: it is the drain call a step-level caller makes
  when its destination, not its input, ran out (measured, §4), and a no-op for
  `read` itself, which loops until nothing is staged. It returns `Ok` with
  nothing written when there is nothing left and no member has ended — that is
  "feed me more", not a stall, and it must not reach the zero-progress guard.
  The guard is for `used == 0 && written == 0` while `src` still has bytes
  left.

Every offset above was measured with `offsetof` against the 2.32.1 pin, not
copied: `block_state` is `uint32_t` at 21,160, `crc_flag` `uint32_t` at 21,172,
`wrapper_flag` `uint16_t` at 21,204, and the two staging cursors sit just before
the history buffer at 21,208 / 21,212.

`istate` is the first field (`Writer` calls its raw zstream `stream` and keeps
`state` for the lifecycle; this follows it), so the existing one-field-cast
trick works unchanged. `wrap` is set once on init and becomes `state->crc_flag`
(`wrapper_code()` already returns ISA-L's 0/1/3). `has_dict` exists because
nothing in an `inflate_state` records whether the caller supplied a dictionary —
the one candidate, `dict_length`, is cleared by both resets — and the stateless
verb has to refuse that combination. Nothing else in the struct is ever written
by *igzip*; only the shim's counters are.

The forged-copy check is `writer_pin`'s, field for field, and it runs first in
every entry point that takes a `Reader`:

```c
static int32_t reader_pin(GooseReader *r) {
	if (!r) return ISAL_INVALID_STATE;
	if (r->wrap > GS_WRAP_ZLIB) return ISAL_INVALID_STATE;
	if (r->state > GS_R_FINISHED) return ISAL_INVALID_STATE;
	/* A dictionary flag with nothing pinned behind it is a deserialized or
	 * forged Reader: the history it names was never copied in. */
	if (r->state == GS_R_FRESH && r->has_dict) return ISAL_INVALID_STATE;

	if (r->state == GS_R_FRESH) {
		if (r->pinned_self == (uint64_t)(uintptr_t)r) return COMP_OK;
		if (r->pinned_self != 0) return ISAL_INVALID_STATE;
		struct inflate_state *s = (struct inflate_state *)(void *)r->istate;
		isal_inflate_init(s);
		/* reset keeps crc_flag and hist_bits; init clears them, so the wrapper
		 * is written here, once, and survives every later reset. */
		s->crc_flag = reader_flag(r->wrap);
		r->pinned_self = (uint64_t)(uintptr_t)r;
		return COMP_OK;
	}

	if (r->pinned_self != (uint64_t)(uintptr_t)r) return ISAL_INVALID_STATE;
	return COMP_OK;
}
```

`igzip_gs_reader_reset` re-writes `s->crc_flag = reader_flag(r->wrap)` after
`isal_inflate_reset` even though that field already survives the reset. Not
because it is necessary, but because the invariant then holds two lines from
where it is relied on instead of three hundred lines away in ISA-L, and the
cost is one store per member.

`total_in`/`total_out` are advanced from the bytes each entry point actually
took and delivered (`*out_consumed` / `*out_written`), never from a delta of
`igzip`'s `total_out` — that field is 32-bit and decreases on the checksum path,
so a delta would wrap a `u64` in the wrong direction.

The `Makefile` moves with that demotion, and the move is part of the change, not
afterthought: `make test` becomes Goose-only and loses its `python3` check,
`make crosscheck` gets the old body, and `make verify` calls `crosscheck`
only when `python3` is on `PATH`.

Acceptance criteria, and how each is checked:

1. **Self-hosting.** `make test` needs no Python and no network. Every stream
   the 0.1.0/0.2.0 suites wrote is decoded in Goose, byte for byte.
2. **Round-trip at every setting.** All wrappers, all levels, empty input,
   incompressible input, block-boundary sizes, the trained table, a dictionary.
3. **Chunked reads are exact.** The same member read in random 1-byte to 1 MiB
   chunks decodes identically to one `inflated` call — a stronger claim than
   "decodes", and the one that catches a missed `copy_overflow`.
4. **Boundaries.** Concatenated members inflate to the concatenation with
   `reset`; trailing garbage after the last member is `BadWrapper`, never
   silently dropped; a partial member is `Truncated`.
5. **Dictionaries.** A zlib stream with FDICT reads with the dictionary and
   fails with `BadChecksum` without it; the same via `set_dict` before any input
   on a raw stream. On `Wrapper.Raw` a wrong dictionary cannot be caught at all
   (§4), so the test pins that it is *not* reported — an undocumented silent
   `Ok` is a security bug, a documented one is a property.
6. **Hostile input.** Truncations at every offset and mutated bytes produce a
   `Status`, never a crash, under `make stress` and the fuzzer.
7. **Memory safety.** `scripts/read_stress.c` green: no write past the
   destination, no read past the chunk, no read of history igzip had already
   dropped. The stateless honesty question is answered (§4); what the harness
   still has to prove is that *this shim* never asks igzip for more than it
   gave it — a 1-byte chunk and a 1-byte input window make every off-by-one a
   fault instead of a wrong byte.
8. **No regressions.** The 43-stream suite still decodes with CPython, the bench
   numbers are unchanged, `Writer`/`Compressor` are untouched byte for byte.
9. **Hygiene.** `make verify && make stress && make fmt-check` green; every new
   struct pinned; no `malloc` in the shim.

## 10. Out of scope

- ~~**`isal_read_gzip_header` / `isal_read_zlib_header`.**~~ **Moved into
  0.3.0** (§12): it was the last capability gap against `igzip_lib.h`, and a
  codec that can write a container it cannot read is not complete. Everything
  else that was out of scope stays out.
- **Checksums** (`crc32_gzip_refl`, `isal_adler32`, and the rest of `crc.h`).
  This was going to be 0.4.0 and the release was dropped instead (§12): igzip
  verifies the trailer itself through `crc_flag`, a caller who wants to know
  whether a stream is intact already asks the `Reader`, and `crc.h` also holds
  `crc16`/`crc64`/`crc32c` that no gzip stream needs. This package verifies
  checksums and does not compute them —
  [../coverage.md](../coverage.md#the-checksum-decision).
- **`isal_create_hufftables_subset`, `isal_deflate_process_dict` /
  `isal_deflate_reset_dict`, `IGZIP_HUFFTABLE_STATIC`** — a table-policy knob, a
  dictionary cache and a third table source; each additive, each with its cost in
  [../coverage.md](../coverage.md).
- **`hist_bits` / window enforcement on decode.** ISA-L does not enforce the
  zlib window on inflate, and a reader that refuses a stream `zlib` accepts is a
  compatibility bug, not a feature.
- **`isal_deflate_process_dict`-style caches, erasure coding, RAID, memory
  kernels.** Do not touch the 0.1.0/0.2.0 API, do not introduce a heap handle,
  do not move `vendor/isa-l` off its pin.

### What the tests found that the brief did not predict

1. **A mutated payload often returns `Ok`.** A single flipped byte inside a
   deflate block usually leaves the stream *unterminated* rather than invalid:
   igzip consumes all the input, emits whatever the corrupted block spelled, and
   reports `ISAL_DECOMP_OK` with `block_state` short of `FINISH`. CPython's zlib
   says the same thing (`eof=False`). So a wrapper's checksum is reached
   *through* completion, not before it, and a caller that never calls `finish`
   cannot tell this stream from one that is simply not finished yet. This is the
   single best argument for `finish` existing, and `test/inflate_contract.goose`
   asserts it explicitly.
2. **`Status.BadState`'s message said "writer state".** It is now "this state",
   since a Reader reaches it too.
3. **`assert(cap < want.len)` is the honest form of the `TooSmall` claim.** The
   first version of the retry test asserted an upper bound on growth and failed
   for a legitimate stream; the property to assert is that `TooSmall` is never
   reported when the destination was big enough, which is also what terminates
   the loop.
4. **A Writer fed in pieces is not byte-identical to one fed the whole body**
   (beyond the level-0 quirk in internals #8). The round-trip test therefore
   compares one-shot against a single `write`, and *decodes* the chunked writer
   rather than comparing it.
5. **`isal_inflate_stateless` is honest about `avail_out`**, confirmed before the
   API relied on it (§4) and pinned afterwards by `scripts/read_stress.c`. The
   brief's stated fallback — dropping `inflate` as a public verb — was not
   needed.

### Second review pass

Three non-blocking nits from review, and three things the review prompted,
applied after the first implementation:

| Item | Change |
|---|---|
| `scripts/read_stress.c` only decoded level 0 | generates level 0 **and** level 1 streams per wrapper. Level 0 is stored and static-Huffman blocks, level 1 is dynamic-Huffman block headers: different decode paths, and both now run under the exact-allocation AddressSanitizer checks |
| `set_dict("")` mid-body returned `Ok` | the legality of the moment is now asked before the empty-dictionary shortcut, so an empty dictionary where a dictionary is not legal is `BadState`. | `Makefile` hardcoded `$(HOME)/.goose` | `GOOSE_HOME` drives both the compiler search and the `libisal.a` lookup, so an unpacked toolchain elsewhere works |
| `TooSmall` left the reader `Fresh` but mid-member | it now resets the decode state, so `Fresh` means it: a caller may retry `inflate` with a bigger slice or switch to `read`, and both start clean. `test/inflate_contract.goose` asserts the switch, which would have failed before |
| `read` had no shim-level test with a small destination | `read_tiny` drives the whole member through `igzip_gs_reader_step` with 1- and 8-byte destinations, which is the only path where the staging drain is real rather than internal |
| keeping the pin across `reset` looked like a free 87 KB memset | measured instead of assumed: `isal_inflate_init` is 3.9 ns and `isal_inflate_reset` 3.4 ns, because init writes a handful of fields and does not clear the tables. ### Header reading, added after the first pass

`isal_read_gzip_header` / `isal_read_zlib_header` were listed out of scope (§10)
and became the one real capability gap: the package could write a container it
could not read. Reading a header is four numbers and three optional byte ranges,
which is not a reason to leave a hole in a codec.

| Question | Decision |
|---|---|
| Whose parser? | **Goose's own**, over a `const u8[:]`. `isal_read_gzip_header` copies name/comment/extra into caller-provided buffers, which means either a 65 KiB temporary or three builders to read four numbers. Parsing over a slice has no pointers to get wrong. |
| What does it return? | `GzipInfo` / `ZlibInfo`: the fields plus **offsets** (`name_at`, `comment_at`, `extra_at`, `body_at`), never copies and never views. A view would dangle as soon as the caller stopped borrowing the buffer; a copy would need somewhere to put 65,535 bytes. `-1` means absent, so one value answers "is it there" and "where". |
| What about a header that ends early? | `Truncated`, and the optional offsets stay `-1`: an offset is worth having only once the whole header has been seen. Every length in the header is checked against the bytes present before it is used, including XLEN and the NUL scan for name and comment. |
| Verify FHCRC? | **No.** `isal_inflate` steps over it, so verifying here and not in the decoder would make the package disagree with itself. `info.hcrc` reports that the field is there. |
| Is `body_at` testable? | Yes, and that is the best test of the whole feature: the bytes from `body_at` decode as a standalone raw stream, which is what `test/header_contract.goose` asserts. It also makes header stripping expressible — feed `gz[info.body_at..]` to a `raw_reader`. |

Making that complete changed the release's claim from "inflate" to "the complete
codec", and retired 0.4.0: checksums are not a codec capability, igzip verifies
trailers itself, and `crc.h` also holds `crc16`/`crc64`/`crc32c` that no gzip
stream needs. The boundary — this package verifies checksums and does not compute
them — is recorded in [../coverage.md](../coverage.md#the-checksum-decision),
along with the three table/dictionary knobs left out by decision.

One claim in the first pass was wrong and is now corrected everywhere it
appeared: `read(r, "", out)` is *not* the drain verb for `read` users. `read`
loops until igzip has nothing left, so it never returns holding staged output,
and an empty source is a no-op for it. The drain matters to a caller driving
`igzip_gs_reader_step` directly, and the empty-source call is kept legal so the
two spellings agree.
