# 0.3.0 design brief: inflate

**Status: design brief. Not implemented.** Sections 1-11 are the problem
statement, the constraints, the proposed surface and the test plan. Section 12
is where the deviations get recorded once this is built, as it was for
[0.2.0](0.2.0.md).

Read [../internals.md](../internals.md) first: the memory model, the pinned
layouts, the FFI review gates and the streaming-value conventions all apply
unchanged.

---

## 1. What the library is, and where it stands

`goose-igzip` binds **igzip** — ISA-L's gzip implementation — to Goose. It is a
Goose package: `igzip.goose` is the entry, `igzip.build` names the CMake target
`igzip_goose`, and `src/igzip_shim.c` is the C adapter. ISA-L 2.32.1 is a pinned
submodule built from source; nothing is installed system-wide.

```bash
make check        # typecheck the package
make test         # Goose tests, then inflate every stream they wrote
make verify       # check + tests + thread test + large test + examples
make stress       # AddressSanitizer check of the output bound
make fmt          # layout is goose format's decision
```

Both halves of *compression* ship today:

| | |
|---|---|
| `Compressor` | 299,472 B — stateless deflate, levels 0-3, raw/gzip/zlib |
| `Writer` | 367,280 B — streaming deflate, custom headers, flush points, dictionary |
| `Trainer`, `Histogram`, `HuffTables` | 18,912 / 2,528 / 2,232 B; trained tables for level 0 |
| `Status` + `ok` / `status_name` | the only failure channel; nothing aborts on bad input |

There is no decompressor. Every test that proves a stream is valid leaves Goose
and runs CPython's `zlib`/`gzip` through `scripts/check_gzip.py`; `make test`
fails if `python3` is missing.

## 2. The problem: this is the version that makes the package a codec

Four things change at once, and they are one design problem because they share
the same state object and the same failure surface.

1. **The package cannot test itself.** A compressor returning `Ok` with a
   plausible size can still emit a broken stream — AGENTS.md says so, and that
   is why the Python checker exists. A decompressor turns every existing test
   into a self-checking one, and is the only way `make verify` can ever run on a
   machine without Python.
2. **`isal_inflate` is stateful and has a different contract from
   `isal_deflate`.** It resumes through `avail_out` reaching zero, sends the
   LZ77 history through its own `tmp_out_buffer`, and signals "member ended"
   with a block state that is *not* an error code. The verb shape has to be
   chosen against that, not copied from `write`.
3. **Input consumption is not total.** Compression consumes every byte handed
   to it. Decompression stops at the end of a member and leaves the rest of the
   slice untouched, which is what makes concatenated members and trailing bytes
   expressible. A `write`-shaped `read(...) -> Status` would silently discard
   that information.
4. **This is the package's first untrusted-input path.** Until now the caller
   fed igzip bytes the caller produced. A decompressor is fed whatever arrived
   on the wire: truncation, bit flips, a fabricated header, a wrapper that
   claims a different method, and the expansion bomb.

The natural consumer is a server that already holds a per-thread `Writer` and
now needs the reverse direction — request bodies, cached entries, proxied
upstreams. Budget accordingly: a `Reader` sits next to a `Writer` for
~152,936 B (below), not another 367 KB.

## 3. Hard constraints

- **C owns no memory.** No `malloc`, no handle to close. State lives in the
  Goose value and the owning scope is the free.
- **No API break.** Every 0.1.0 and 0.2.0 signature keeps working and producing
  the same bytes.
- **Layouts pinned.** Every new mirrored C struct gets `_Static_assert`s for
  size, alignment, and each offset the shim reads.
- **Build shape unchanged.** Native code is the CMake target `igzip_goose`; no
  `c_libs`, no `extern "isal"` block, no system install.
- **Goose has no named arguments, no tuples, no `?`, and no truthiness.** A call
  site reads positionally; a `Status` needs `.ok()`; a group of results is a
  multiple return (`-> i64, Status`), not a struct.
- **No progress is never a hang.** Every drain loop gets the `write_window`
  guard: `used == 0 && written == 0` is a `Status`, never an infinite loop.

## 4. ISA-L facts you can rely on

Measured against the vendored 2.32.1 pin unless marked otherwise.

### The state value

| Item | Value | Consequence |
|---|---|---|
| `sizeof(struct inflate_state)` | **87,368 B**, align 8 | the reader's whole state; no level buffer, no hufftables pointer |
| `lit_huff_code` / `dist_huff_code` | 18,912 / 2,208 B | most of the 87 KB: decode lookup tables, rebuilt per block |
| `tmp_out_buffer` | 65,824 B (`2*32768 + 288`), offset 21,544 | igzip's own 64 KiB history; a drain through a 64 KiB chunk cannot lose it |
| `tmp_in_buffer` | 328 B | header bytes held across a chunk boundary |
| `total_out` | `uint32_t`, offset 12 | wraps exactly like gzip's ISIZE, which is why `check_gzip_checksum` compares a wrapped value — accumulate a `u64` in Goose from per-call deltas |
| `block_state`, `crc_flag`, `wrapper_flag` | offsets 21,160 / 21,172 / 21,204 | completion, wrapper, and "header already parsed" |

### The functions

| Fact | Consequence for the design |
|---|---|
| `void isal_inflate_init(struct inflate_state *)` / `isal_inflate_reset` | reset clears `wrapper_flag`, `dict_length`, `tmp_in_*`, `tmp_out_*` and the overflow cursors, but **not** `crc_flag` or `hist_bits` — exactly right for the next concatenated member |
| `int isal_inflate(struct inflate_state *)` returns `ISAL_DECOMP_OK` (0) or a negative error | the tail is `return (ret > 0) ? ISAL_DECOMP_OK : ret`, and the only positive code that escapes is `ISAL_NEED_DICT`. **"Done" is `block_state == ISAL_BLOCK_FINISH`, not a return code** |
| `isal_inflate` resumes after `avail_out == 0` via `copy_overflow_length` / `write_overflow_*` into `tmp_out_buffer` | an honest `avail_out` every call is the whole contract; a chunked drain is safe and byte-identical to a one-shot (asserted in the tests, not assumed) |
| with input exhausted mid-block and `avail_out > 0`, `isal_inflate` returns 0 and consumes everything | truncation is *observable only* as `block_state != FINISH`; `read` must not bend this into `Corrupt` |
| `isal_inflate_stateless` resets its own decode fields on entry and decodes exactly one member | a retry with a bigger destination is well-defined; trailing bytes are left in `avail_in` |
| `isal_inflate_stateless` returns `ISAL_END_INPUT` (1) when the final block was never reached | the roadmap's "truncated input is its own `Status`", for free |
| `isal_inflate_stateless` (**documented**) does not support dictionaries | `NeedDict` is the answer there; dictionary streams work through the streaming path |
| `isal_inflate_set_dict` memcpy's at most `IGZIP_HIST_SIZE` (32 KiB) of the tail into `tmp_out_buffer` and requires `block_state == NEW_HDR && tmp_out_processed == tmp_out_valid` | the slice does not outlive the call, and the legal moment is "before any output", which includes *just after* `ISAL_NEED_DICT` |
| a zlib stream with FDICT makes `isal_inflate` parse the header, store `dict_id`, and return `ISAL_NEED_DICT` (6) | `read` must report it *with the header bytes consumed* so the caller can supply the dictionary and continue from the same offset |
| **`dict_id` is stored and never compared** (`igzip_inflate.c` 2114 / 2257; no comparison anywhere) | a wrong dictionary is not caught at `set_dict`; it surfaces as a corrupt stream or as `ISAL_INCORRECT_CHECKSUM` at the trailer. Say so, and pin it with a test |
| return codes: `ISAL_DECOMP_OK 0`, `END_INPUT 1`, `OUT_OVERFLOW 2`, `NEED_DICT 6`; `INVALID_BLOCK -1`, `INVALID_SYMBOL -2`, `INVALID_LOOKBACK -3`, `INVALID_WRAPPER -4`, `UNSUPPORTED_METHOD -5`, `INCORRECT_CHECKSUM -6` | **-1 and -3 collide with the deflate family's `STATELESS_OVERFLOW` and `ISAL_INVALID_STATE`**, so one shared `status_of` cannot serve both. The shim must translate (Q8) |
| `ISAL_DEFLATE 0`, `ISAL_GZIP 1`, `ISAL_ZLIB 3` are the `crc_flag` values | `wrapper_code()` already returns 0/1/3, so the same Goose `Wrapper` maps directly |
| no globals in `igzip_inflate.c`; every byte is in the caller's struct or lent for one call | a `Reader` per `thread_fn` works exactly like a `Writer`, with no `main_thread_only` |

## 5. Design questions

### Q1 — One `Reader`, or a streaming type plus a one-shot type?

`isal_inflate_stateless` needs the same 87,368-byte `inflate_state` as
`isal_inflate`, so a separate `Inflate` type would duplicate the largest part of
the value for anyone who wants both paths.

**Recommend: one value, two modes.** `Reader` carries the state, a 64 KiB chunk,
a wrapper, a phase and a copy guard; `read`/`finish` drive `isal_inflate`, and
`inflate` is the direct `isal_inflate_stateless` exposure, with `inflated` as the
fresh-builder convenience on top of the streaming loop. The phase enum already
distinguishes the legal moments, so there is no extra mode flag.

### Q2 — Naming

The roadmap says `Inflater` "matching `Deflater`", but the type that shipped is
`Writer`. gslib's prior art is `GzipReader` / `gzip_reader` / `gzip_read`.

**Recommend `Reader`**, with `reader(wrap)`, `gzip_reader()`, `zlib_reader()`,
`raw_reader()`, and the streaming verb `read` so the two shapes line up:

```goose
w.write(plain, out);        r.read(gz, out);        // streaming
c.compress(plain, out);     r.inflate(gz, out);     // one-shot, caller's room
c.compressed(plain);        r.inflated(gz);         // one-shot, fresh buffer
```

`inflate`/`inflated` keep ISA-L's own word for decompression, which is also what
a caller searching for "inflate" will type.

### Q3 — Where does output go?

Same two shapes as 0.2.0, plus one that only exists for inflate.

(a) **owned 64 KiB chunk, appended per call** — proven by `Writer`, works with a
destination builder that has zero free space.
(b) **decode straight into the builder's free space** and claim what igzip
wrote. No copy, but Goose offers no `reserve` on a builder, so a builder with no
slack leaves `avail_out == 0`; the loop would have to `resize` up and down, and
growing an array while an outstanding `const u8[:]` views it is not legal Goose.
(c) **caller-sized destination, no staging** — this is what the *stateless* verb
needs anyway, because igzip cannot say how much output a member will produce.

**Recommend (a) for `read`/`finish` and (c) for `inflate`.** The chunk is 64 KiB
on top of 87 KB; that is the whole budget: **`Reader` = 152,936 B** (87,368
state + 65,536 chunk + 3 u64 counters + 3 bytes of flags).

### Q4 — What does `read` return?

Compression consumes everything, so `write(...) -> Status` is complete.
Decompression stops at a member boundary with bytes left over, and a caller that
cannot see where needs to re-scan the buffer or re-feed it — a correctness
error waiting to happen for concatenated members and trailing bytes.

**Recommend `fn read(r: Reader&, src: const u8[:], out: u8[>..]&) -> i64, Status`**
returning the number of *compressed* bytes consumed. The loop stops when `src` is
exhausted **or** the member ends. `consumed == src.len && r.finished()` is the
common one-member case, and it reads as one condition.

```goose
var r = igzip::gzip_reader();
var body: u8[>..] = [];
let used, err = r.read(gz, body);
guard err.ok() else { abort(igzip::status_name(err)); };
guard r.finished() else { /* need more input */ };
// gz[used..] is not this member's: trailing bytes or the next member.
```

`read` windows its input at `MAX_INPUT` like `write`, and exposes the same
`read_windowed(r, src, out, step)` test seam so the 32-bit path is reachable
without a 2 GiB slice. A `src` past `MAX_INPUT` is windowed, never rejected.

### Q5 — Concatenated members: automatic or explicit?

`gzip.decompress` concatenates; Go defaults `Multistream` to on; gslib carries a
`multistream` flag to turn that off. A streaming consumer that must know where a
member ends cannot use a silent auto-reset, and a whole-buffer consumer does not
want to write the loop.

**Recommend: explicit in the streaming path, automatic in the whole-buffer
verb.** `read` stops at a boundary and the caller calls `reset(r)` to start the
next member; `inflated(r, src)` loops members itself. No mode flag: `consumed`
plus `finished(r)` already expresses both policies, and a flag would make the
two features disagree.

```goose
// whole buffer: every member, none left behind
let plain, err = r.inflated(two_members);

// streaming: know exactly where member N ends
var pos: i64 = 0;
loop {
    let used, err = r.read(buf[pos..], out);
    if err != igzip::Status.Ok { break; }
    pos += used;
    if !r.finished() { break; }        // truncated, or a partial chunk
    if pos == buf.len { break; }
    r.reset();
}
```

### Q6 — Truncation

Three distinguishable situations, three answers:

| Situation | Reported |
|---|---|
| input ends mid-block, streaming, caller says there is no more | `finish(r, out)` → `Status.Truncated` |
| input ends mid-block, whole buffer | `inflate`/`inflated` → `Status.Truncated` (ISA-L's `ISAL_END_INPUT`, mapped) |
| input ends mid-block, but the caller has more coming | nothing: `read` returns `Ok`, `finished(r)` is false |

`Truncated` is a distinct variant, never `Corrupt`: truncated data is the normal
case for a cut-off transfer and the remedy (feed more, or re-fetch) is different
from the remedy for damaged bytes (drop it).

### Q7 — Dictionaries

`set_dict` is legal where igzip says it is, which for a *reader* means two
moments, not one:

- **`Fresh`**, before any input: the raw-stream route, and the zlib route where
  the caller knows the stream needs it.
- **`Open`, immediately after `Status.NeedDict`**: the zlib FDICT route. The
  header has been parsed, `block_state` is `NEW_HDR`, no output has been
  produced, and igzip's own guard accepts it. This is the common case for a
  reader and must not be refused.

Two facts the API must state rather than hide: igzip copies the last 32 KiB, so
the slice need not outlive the call; and igzip **never compares the supplied
dictionary to the stream's DICTID**, so a wrong dictionary is reported as
`BadChecksum` at the trailer (or `Corrupt` earlier), not at `set_dict`. The
tests pin exactly that.

`reset(r)` drops the dictionary (`isal_inflate_reset` clears `dict_length`), so
a caller reusing a reader for another dictionary stream re-sets it. `reset`
keeps the wrapper, and it must: `crc_flag` survives igzip's reset by design,
which is why the next member's trailer is still verified.

### Q8 — `Status` additions, and the return-code collision

The deflate family maps `-1` to `Overflow` and `-3` to `BadState`; the inflate
family uses `-1` for `ISAL_INVALID_BLOCK` and `-3` for `ISAL_INVALID_LOOKBACK`.
One shared `status_of` table cannot be right for both, and a "look at the call
site" rule is the kind of thing that survives right up until a helper forwards
an `rc`.

**Recommend: the shim translates.** `igzip_gs_reader_*` returns package codes in
a range disjoint from ISA-L's, so `status_of` stays one table and every call site
keeps working:

```c
#define IGZIP_GS_TRUNCATED  (-11)
#define IGZIP_GS_NEED_DICT  (-12)
#define IGZIP_GS_TOO_SMALL  (-13)
#define IGZIP_GS_CORRUPT    (-14)
#define IGZIP_GS_BAD_SUM    (-15)
```

and five new variants, each with an accurate `status_name`:

| Variant | Meaning | From |
|---|---|---|
| `Truncated` | input ended before the member's final block | `ISAL_END_INPUT`, or `!finished` at `finish` |
| `TooSmall` | the caller's destination had no room for the decoded bytes | `ISAL_OUT_OVERFLOW` |
| `NeedDict` | a zlib stream requires a preset dictionary | `ISAL_NEED_DICT` |
| `Corrupt` | the bytes are not a valid deflate stream | `INVALID_BLOCK`, `INVALID_SYMBOL`, `INVALID_LOOKBACK` |
| `BadChecksum` | the trailer does not match the decoded bytes | `INCORRECT_CHECKSUM` |

Reused: `BadWrapper` for `INVALID_WRAPPER` and `UNSUPPORTED_METHOD` (a file
that is not gzip, or gzip with `CM != 8`), `BadState` for `ISAL_INVALID_STATE`,
and `Overflow` keeps its compression-only meaning ("input too large for igzip's
32-bit lengths") so no caller can misread it. `Corrupt` collapses three ISA-L
codes because the caller's remedy is identical for all three; a caller that
wants the exact symbol asks ISA-L, not this package.

### Q9 — Expansion limits

There is no `bound` for decompression: a 300-byte input may legitimately expand
to gigabytes. That is a hazard for any server that decompresses a request body.

**Recommend: no limit parameter in the 0.3.0 surface.** `read` plus
`r.total_out` is already a limit — a caller stops feeding input when the output
passes its cap, which is strictly better than aborting mid-member.
`inflated`/`inflate` are for buffers whose size the caller already trusts, and
their doc comment says so. Revisit (`inflated(r, src, limit)` as an additive
overload) if a real caller asks.

### Q10 — Copy semantics

Goose copies fixed-size values by assignment. A copied `Reader` is *memory-safe*
— unlike a copied `Writer`, no internal pointer is left dangling, because
`inflate_state` holds no pointer into Goose memory between calls — but both
copies decode from the same position and emit the same bytes twice. Silent
duplication is a bug worth a `Status`.

**Recommend: keep the guard.** Reuse the `Writer`'s `pinned_self` pattern
(lazy init records the value's address; any later call from another address is
`BadState`; `reset` recovers), so the package has one rule for stateful values
rather than a per-type footnote. The shim also clears `next_in`/`next_out` after
every call, the same way `igzip_gs_writer_step` does.

## 6. The proposed surface

```goose
enum ReaderState { Fresh, Open, Finished }

struct Reader {
    state:       u64[10921]      = [0; 10921]   // sizeof(inflate_state) = 87,368
    chunk:       u8[CHUNK_SIZE]  = [0; CHUNK_SIZE]
    pinned_self: u64             = 0
    total_in:    u64             = 0
    total_out:   u64             = 0
    wrap:        Wrapper         = Wrapper.Gzip
    phase:       ReaderState     = ReaderState.Fresh
    has_dict:    bool            = false
}

fn reader(wrap: Wrapper) -> Reader
fn gzip_reader() -> Reader
fn zlib_reader() -> Reader
fn raw_reader() -> Reader

fn read(r: Reader&, src: const u8[:], out: u8[>..]&) -> i64, Status
fn read_windowed(r: Reader&, src: const u8[:], out: u8[>..]&, step: i64) -> i64, Status
fn finish(r: Reader&, out: u8[>..]&) -> Status
fn reset(r: Reader&) -> Status
fn finished(r: Reader&) -> bool

fn set_dict(r: Reader&, dict: const u8[:]) -> Status

fn inflate(r: Reader&, src: const u8[:], out: u8[>..]&) -> i64, Status
fn inflated(r: Reader&, src: const u8[:]) -> u8[>..], Status

fn total_in(r: Reader&) -> i64
fn total_out(r: Reader&) -> i64
fn reader_size() -> i64
```

Notes on the verbs:

- `read`/`finish` operate on `isal_inflate`; `inflate` on
  `isal_inflate_stateless`. The one-shot verbs are legal only in `Fresh` and
  leave the reader `Finished`; `reset` is how either mode starts the next body.
  Mixing them inside one body is `BadState`, not undefined.
- `inflate` is the direct stateless exposure and needs the destination to fit:
  that is the roadmap's "whole-buffer read", and the only verb that can answer
  `TooSmall`.
- `inflated` does **not** call the stateless function. It drives the streaming
  loop: a fresh builder cannot be sized ahead of time, the streaming path needs
  no guess, and it is what lets a dictionary work through `inflated`.
- `finish` drains whatever the last `read` left staged, then reports
  `Truncated` if `finished(r)` is false. It is the mirror of `Writer.finish`
  (the return code, not the data, is the point).
- `finished` is the completion predicate for both modes: `block_state ==
  ISAL_BLOCK_FINISH`. It is the one thing `isal_inflate` cannot tell you through
  its return value.
- `total_in`/`total_out` are `u64` accesses rather than public fields, because
  igzip's own `total_out` is 32-bit: the shim accumulates deltas and the value
  never wraps at 4 GiB.

## 7. The C shim

Four new entry points, in the shape of the writer's:

```c
int32_t igzip_gs_reader_size(void);
int32_t igzip_gs_reader_reset(GooseReader *r);
int32_t igzip_gs_reader_set_dict(GooseReader *r, igzip_slice_u8 dict);

/* Streaming: one drain step against the 64 KiB chunk. `out_finished` is
 * block_state == ISAL_BLOCK_FINISH; `out_consumed` is the caller's compressed
 * bytes taken. */
int32_t igzip_gs_reader_step(GooseReader *r, igzip_slice_u8 src, igzip_slice_u8 dst,
                             uint32_t *out_consumed, uint32_t *out_written,
                             bool *out_finished);

/* Stateless: igzip writes at out.stk->top, and only the bytes it reports are
 * claimed, exactly as igzip_gs_compress does. */
int32_t igzip_gs_reader_stateless(GooseReader *r, igzip_slice_u8 src, gs_rref out,
                                  uint32_t *out_consumed);
```

The mirror and its asserts:

```c
typedef struct {
        uint64_t state[sizeof(struct inflate_state) / 8];
        uint8_t chunk[GS_CHUNK];
        uint64_t pinned_self;
        uint64_t total_in;
        uint64_t total_out;
        uint8_t wrap;
        uint8_t phase;
        bool has_dict;
} GooseReader;

_Static_assert(sizeof(struct inflate_state) == 87368, "inflate_state size changed");
_Static_assert(_Alignof(struct inflate_state) <= 8, "inflate_state needs more alignment than u64 gives");
_Static_assert(sizeof(GooseReader) == 152936, "Reader size changed; update igzip.goose");
_Static_assert(offsetof(GooseReader, chunk) == 87368, "Reader.chunk offset");
_Static_assert(offsetof(GooseReader, pinned_self) == 152904, "Reader.pinned_self offset");
_Static_assert(offsetof(struct inflate_state, block_state) == 21160, "block_state offset");
_Static_assert(offsetof(struct inflate_state, crc_flag) == 21172, "crc_flag offset");
_Static_assert(offsetof(struct inflate_state, wrapper_flag) == 21204, "wrapper_flag offset");
_Static_assert(offsetof(struct inflate_state, tmp_out_buffer) == 21544, "tmp_out_buffer offset");
_Static_assert(sizeof(((struct inflate_state *)0)->tmp_out_buffer) == 65824, "history buffer size");
```

`state` is the first field, so the existing `Compressor_g`
one-field-cast trick works unchanged. `wrap` is set once on init and becomes
`state->crc_flag` (`wrapper_code()` already returns ISA-L's 0/1/3); nothing else
in the struct is ever written by igzip.

## 8. Tests, mapped to the roadmap

The roadmap's fourth bullet is the acceptance test for the other three: a
round-trip that needs no Python.

| File | Covers |
|---|---|
| `test/inflate_contract.goose` (new) | the state machine (`Fresh`/`Open`/`Finished`, every misuse a `BadState`), the copy guard, `Truncated`, `NeedDict` and the resume-after-`NeedDict` sequence, `Corrupt` from bit flips and fabricated headers, `BadChecksum` from a wrong dictionary, `BadWrapper` from non-gzip bytes and from gzip with a bad method, `reader_size()` |
| `test/roundtrip.goose` (new) | **the headline.** For every wrapper × level 0-3 and a ladder of sizes: compress, then `read` in random chunks and in one window, and compare to the input; `inflated` of the same; trained-table streams; the empty body; concatenated members |
| `test/support/support.goose` (extend) | the corpus generator becomes the shared reference body for both directions; a `mutate` helper producing corrupt variants |
| `test/streaming.goose` (extend) | flush points are decode points *in Goose*: `read` only the prefix up to a `Sync`/`Full` flush and get every input byte so far, then the rest; a `Full` flush's following block decodes with the prefix discarded |
| `test/writer_contract.goose` (extend) | every custom-header stream the writer produced decodes: a `GzipHeader` with all fields set, a header larger than the 64 KiB chunk, and a zlib header with a reduced `window_bits` are read back to the same body. Header *inspection* stays out of scope (§10); this only proves a reader accepts what a writer emits |
| `test/threads.goose` (extend) | a `Reader` worker per `thread_fn`, decoding what a `Writer` worker produced in another thread; no globals |
| `test/large_stream.goose` (extend) | inflate the 4.2 GiB gzip member the writer test produces, in windows, asserting `total_out` (u64, past igzip's 32-bit `total_out`) and that the trailer's wrapped ISIZE still verifies |
| `scripts/read_stress.c` (new) | AddressSanitizer: `inflate` into a destination of exactly the decoded size, and one byte short; `read` with a 1-byte output chunk; truncation at every byte offset; hundreds of random mutations. It answers the one question the API cannot assume: **is `isal_inflate_stateless` honest about `avail_out`, or does it overrun like `isal_deflate_stateless`?** |
| `scripts/check_gzip.py` (demoted) | keeps `make crosscheck`, not `make test`. A compressor and a decompressor wired to each other can agree on a broken stream; CPython's `zlib` is the only decoder here that is not ours, and six lines of CI is cheap insurance. `make verify` runs it when `python3` exists. |

Acceptance criteria, and how each is checked:

1. **Self-hosting.** `make test` needs no Python and no network. Every stream
   the 0.1.0/0.2.0 suites wrote is decoded in Goose, byte for byte.
2. **Round-trip at every setting.** All wrappers, all levels, empty input,
   incompressible input, block-boundary sizes, the trained table, a dictionary.
3. **Chunked reads are exact.** The same member read in random 1-byte to 1 MiB
   chunks decodes identically to one `inflated` call — a stronger claim than
   "decodes", and the one that catches a missed `copy_overflow`.
4. **Boundaries.** Concatenated members inflate to the concatenation with
   `reset`; trailing garbage after the last member is `BadWrapper`, never
   silently dropped; a partial member is `Truncated`.
5. **Dictionaries.** A zlib stream with FDICT reads with the dictionary and
   fails with `BadChecksum` (or `Corrupt`) without it; the same via `set_dict`
   before any input on a raw stream.
6. **Hostile input.** Truncations at every offset and mutated bytes produce a
   `Status`, never a crash, under `make stress` and the fuzzer.
7. **Memory safety.** `scripts/read_stress.c` green: no write past the
   destination, no read past the chunk, no reliance on igzip's honesty that the
   stress run has not proven.
8. **No regressions.** The 43-stream suite still decodes with CPython, the bench
   numbers are unchanged, `Writer`/`Compressor` are untouched byte for byte.
9. **Hygiene.** `make verify && make stress && make fmt-check` green; every new
   struct pinned; no `malloc` in the shim.

## 9. Risks, and what to cut first

| Risk | Mitigation | If it wins |
|---|---|---|
| `isal_inflate_stateless` overruns an exact-size destination the way `isal_deflate_stateless` does | `scripts/read_stress.c` measures it before the API trusts it; the shim claims only reported bytes | drop `inflate` as a public verb and make `inflated` (streaming internals) the only one-shot; the stateless call stays a shim-internal step |
| A chunked drain differs from a one-shot read (a missed history or overflow cursor) | criterion 3 asserts exact equality at random chunk sizes; the large test crosses the 32-bit boundary | ship `inflated` only, and gate `read` behind the failing test until fixed |
| The `NeedDict` resume sequence is off by the DICTID bytes | one test feeds the header, stops at `NeedDict`, sets the dictionary and continues from `consumed`; another feeds everything in one call | require `set_dict` before any input only (a smaller surface, worse for streamed zlib) |
| The status translation is wrong for one code | table-driven unit test in `inflate_contract.goose` with a hand-built corrupt stream per family | keep ISA-L's raw codes and give Goose a per-family mapper |
| Two stateful values per thread (~520 KB) hurt | measured, not guessed: report it in the README beside the existing sizes | share the chunk between `Writer` and `Reader` — the honest cut, one 64 KiB buffer instead of two |
| Scope creep: header inspection (`isal_read_gzip_header`), checksums, window enforcement | explicitly out of scope below | the first thing to cut; none of it is needed for a round-trip |

Order of work, so a partial result is still useful: **state value + stateless
`inflate` + round-trip tests** first (that alone retires the Python dependency
for the existing suite), then streaming `read`/`finish`/`reset` with chunked
equality, then dictionaries, then the fuzzer and the stress harness.

## 10. Out of scope

- **`isal_read_gzip_header` / `isal_read_zlib_header`** as public API. Parsing a
  header for its mtime/name is a nice feature and a different one; the wrapper
  already validates what it must. Additive later.
- **Checksums** (`crc32_gzip_refl`, `isal_adler32`) — 0.4.0. igzip verifies the
  trailer itself through `crc_flag`, and that is all 0.3.0 needs.
- **`hist_bits` / window enforcement on decode.** ISA-L does not enforce the
  zlib window on inflate, and a reader that refuses a stream `zlib` accepts is a
  compatibility bug, not a feature.
- **`isal_deflate_process_dict`-style caches, erasure coding, RAID, memory
  kernels.** Do not touch the 0.1.0/0.2.0 API, do not introduce a heap handle,
  do not move `vendor/isa-l` off its pin.
